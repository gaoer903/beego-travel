# 避过 · 数据采集器（crawler）

把**政府公开公告**结构化成 JSON，供人工复核后入库。这是一个**独立工具**，不属于 Nuxt 应用代码，不参与前端构建。

## 合规边界（务必先读）

采集严格遵循之前的可行性 & 法律分析结论：

| 可以 | 不可以 |
| --- | --- |
| ✅ 政府公开公告（文旅部、各省文旅厅、消协公示） | ❌ 黑猫投诉 / 大众点评 / 美团等商业平台 UGC（诉讼风险） |
| ✅ 注明来源、保留原文链接 | ❌ 存储 / 展示个人身份信息（姓名、手机号、身份证） |
| ✅ 正文摘要（截断） | ❌ 全文照搬商业平台内容 |
| ✅ 礼貌抓取（限速、UA、尊重 robots.txt） | ❌ 点对点指控具体个人 |

> 采集到的数据为「**原始池 / 待核实**」形态，**不可直接上线**。
> 按产品策略，需经「多源交叉 + 数据团队过审」后才标记为「已核实」。

## 数据源（白名单）

见 `sources.ts`。当前内置：

- **文化和旅游部 · 文化要闻** — 旅游市场强制消费典型案例、严重失信主体名单
- **北京市文旅局 · 旅行社投诉量公示** — 每周投诉量前十旅行社 + 问题类型

## 用法

```bash
# 抓取全部源（默认：文旅部 30 条 + 北京 30 条，自动翻列表分页）
npm run crawl

# 尽量抓满当前列表分页上的全部条目
npm run crawl:full

# 只抓某个源
npm run crawl -- --source=mct
npm run crawl -- --source=beijing

# 自定义每源上限
npm run crawl -- --limit=50
```

结果写入 `crawler/output/<source>.json`，并在控制台打印预览。

## 输出字段

```jsonc
{
  "source": "mct",                       // 源标识
  "sourceName": "文化和旅游部政府门户",   // 来源名称（前端「来源」标注）
  "sourceUrl": "https://www.mct.gov.cn/...", // 原文链接（注明出处）
  "title": "旅游市场强制消费问题典型案例（2026年第一批）",
  "publishDate": "2026-02-11 18:00",
  "category": "文旅部通报",
  "summary": "正文摘要（截断、已脱敏）…（详见原文链接）",
  "crawledAt": "2026-05-30T..."          // 采集时间
}
```

## 下一步（采集 → 入库的完整链路）

1. **AI 清洗**：把 `summary` 用 DeepSeek 抽成结构化字段（city / category / place / 聚合描述），对齐 `src/types` 的 `Incident`
2. **写入 pending 池**：`status=pending`
3. **人工复核**：数据团队一键标记 `verified`
4. **多源交叉**：≥2 来源交叉后才上线「已核实」

## 技术说明

- 零运行时依赖，仅用 Node 内置 `fetch` / `TextDecoder` / `fs`
- 通过 `tsx` 运行 TS（已在 devDependencies）
- 自动识别页面 charset（兼容政府站常见的 gb2312/gbk）
- 请求间隔 1.5s 限速；自定义 User-Agent；20s 超时
